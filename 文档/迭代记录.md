OpsAgent 项目迭代记录
 
  OpsAgent 从最初的简易命令行脚本持续迭代，逐步完善为具备 Web 交互能力、安全管控机制、跨主机远程执行能力的完整智能运维 Agent 工程化产品。整体经历四个阶段性版本迭代，完成从文本问答到自动化故障排查工具的完整升级。
 
V1 基础诊断期——实现大模型问答与日志分析能力
 
  本版本核心目标为打通大模型调用链路，实现基础运维日志智能分析功能。
  基于 Python 搭建项目运行环境，通过环境变量文件统一管理配置信息。调用智谱 GLM-4 大模型接口，实现终端端的持续问答交互循环。通过规范化提示词约束模型输出格式，使大模型可自动完成问题诊断、原因分析、解决方案梳理，输出结构化运维诊断报告。
  该版本解决了传统运维人工检索故障方案、手动整理排查步骤效率低下的问题，初步实现运维问题智能化解答。
 
V2 知识库优化期——降低模型幻觉、提升诊断专业性
 
  本版本核心目标为优化大模型运维场景适配性，解决模型答非所问、主观臆断的幻觉问题。
  搭建轻量化运维标准流程知识库，以本地结构化文件存储运维标准化操作规范，通过关键词匹配机制将专业运维 SOP 动态注入对话上下文，提升故障诊断的精准度。优化输出规范，强制模型输出可直接复制执行的运维命令，大幅提升工具落地实用性。补充异常场景处理逻辑，在无明确报错日志的场景下，引导通过系统退出码排查隐性故障，避免无效推理。
  该版本让大模型的回答从通用泛化解答，升级为贴合运维标准、可直接落地的标准化排查方案。
 
V3 Agent 架构建设期——赋予模型自主远程执行能力
 
  本版本核心目标为突破纯文本问答局限，构建可自主推理、自主操作的智能运维执行体系。
  引入 ReAct 推理循环与函数调用机制，使大模型具备自主决策能力，可根据故障场景自主选择运维命令、执行操作，并依据返回结果迭代推理，直至完成故障排查。基于 paramiko 模块搭建 SSH 通信链路，实现 Windows 宿主机对 Ubuntu 虚拟机的跨主机远程操控。
  搭建多层安全管控机制，设计运维命令白名单策略，白名单外操作需人工确认，高危破坏性命令直接强制拦截，规避误操作风险。接入 MySQL 数据库，完整记录模型推理过程、执行命令、返回结果与操作耗时，实现运维操作全流程审计追溯。
  该版本将工具从运维咨询工具升级为具备自主执行能力的自动化故障排查载体，真正实现 AI 运维落地应用。
 
V4 Web产品化升级期——完成工程化、可视化、安全化落地
 
  本版本核心目标为优化产品交互形态，解决终端工具使用局限，完善工程化与安全体系。
  基于 Flask 搭建网页交互界面，通过前端异步请求技术实现前后端数据交互，替代传统命令行操作，打造可视化运维对话平台。设计滑动窗口对话记忆机制，实现多轮连贯对话，同时规避上下文过长导致的令牌溢出问题。
  重构人机协同授权架构，设计异步令牌确认机制，解决终端阻塞主线程的架构缺陷。后端识别高危操作后向前端推送确认指令，由用户手动授权或拒绝，实现安全可控的人机协同运维。重构安全校验优先级体系，提升高危命令拦截权限，修复潜在的误执行漏洞，构建严密的运维安全防线。
  该版本完成工具从脚本原型到标准化 Web 工程产品的蜕变，兼顾使用体验、运行稳定性与操作安全性。
